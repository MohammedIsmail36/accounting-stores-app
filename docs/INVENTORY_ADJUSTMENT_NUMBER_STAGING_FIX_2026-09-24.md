# إصلاح أول ترحيل لتسوية المخزون على Staging

النطاق: فرع `feature/inventory-control-staging` وموقع وقاعدة Staging فقط. لا تغيير في Farida أو Alibea.

## المشكلة والقرار

- محاولة ترحيل المسودة `#18` فشلت في المتصفح قبل إرسال الطلب لأن دالة `supabase.rpc` فُصلت عن كائنها، فتسببت برسالة `Cannot read properties of undefined (reading 'rest')`. أثبت الفحص أن المسودة بقيت `draft`، وأنها لم تُنشئ حركة أو قيدًا أو عملية ذرية.
- الرقم `adjustment_number` داخلي ويُخصص عند إنشاء المسودة. سيُعرض مثل فواتير المبيعات والمشتريات بصيغة `#18` دون بادئة. الرقم الرسمي `posted_number` يُخصص فقط داخل معاملة الترحيل الناجحة؛ يعرض `ADJ-0001` عند أول ترحيل جديد. حذف مسودة لا يستهلك رقمًا رسميًا.
- السجلات القديمة المعتمدة أو المرحّلة تحتفظ بعرض أرقامها التاريخية دون إعادة ترقيم. حجز أرقامها يمنع تعارضها مع الأرقام الرسمية الجديدة. المسودة المحفوظة تظل بنفس معرفها وبياناتها.
- اختيار وعرض المنتج يستعملان تنسيق الفواتير المشترك: `[الكود] الاسم - الماركة - الموديل`. أُضيف توضيح لرقم المسودة واتسع عمود المنتج دون إعادة بناء الجدول بمكوّن مكرر.

## الضمانات

- تخصيص الرقم الرسمي محمي بقفل معاملات وفهرس فريد؛ فشل أي خطوة في الترحيل يُعيد الرقم والكمية والحركة والقيد معًا، بلا فجوة ناتجة عن محاولة فاشلة.
- لا يستطيع عميل API ضبط الرقم الرسمي مباشرة. ملف الرجوع يرفض العمل بعد تسجيل أول عملية ترحيل فعلية؛ بعد ذلك يكون التصحيح الأمامي هو المسار الآمن.
- نسخة Staging قبل أول ترحيل فعلي: `/backups/staging/inventory-atomic-before-first-post-Y55D3y`، ونسخة واجهتها قبل الإصلاح: `/opt/backups/accounting-app/staging-inventory-atomic-ui-before-Cg9F3L`.
- دليل تجربة الترحيل والتكرار والرجوع والتحقق بعد النشر: `/backups/staging/inventory-atomic-before-first-post-Y55D3y/posted-number-postapply`، مع بصمات SHA256.

## حالة القبول الحالية

نجحت 22 وحدة اختبار مستهدفة وTypeScript والبناء المعزول وتجربة SQL المعاملاتية وملف الرجوع. طُبقت Migration `20260924105000` ونُشرت الواجهة على Staging. ثم رحّل المستخدم المسودة `#18` عبر المتصفح، ونالت الرقم الرسمي `ADJ-0001`.

تحقق القبول للقراءة فقط من انتقال كمية المنتج `PRD-330` من 5 إلى 6، وحركة مخزون واحدة بقيمة 108 EGP، وقيد مرحّل واحد متوازن برقم `JV-0323` (1104 مدين و4201 دائن، 108 EGP لكل منهما)، وربط العملية والقيد وتوقيعها. زادت قيمة المخزون وحساب 1104 بالقيمة نفسها، وبقي الفرق التاريخي بينهما 0.02 EGP دون فرق كمية أو أثر مكرر. حُفظ الدليل وبصماته في `/backups/staging/inventory-atomic-before-first-post-Y55D3y/first-post-acceptance`.

بعد هذا الترحيل الفعلي، يرفض ملف رجوع بنية الترقيم والعمل الذري إزالة مكونات تحوي سجل العملية. أي تصحيح لاحق يجب أن يكون أماميًا ومحكومًا، ولا يُختبر عكس التسوية إلا بقرار منفصل بعد مراجعة أثره.
