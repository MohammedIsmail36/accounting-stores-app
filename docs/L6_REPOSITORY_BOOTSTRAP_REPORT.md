# تقرير تجهيز مستودع L6 النظيف

> التاريخ: 2026-09-07
> النطاق: `/opt/accounting-app-cleanroom` فقط
> الحالة: تجهيز وفحص الملفات والالتزام الأول وربط GitHub ودفع `main` مكتملة؛ حماية الفرع واختبار clone جديد ما زالا معلقين

## الهدف

إنشاء تاريخ Git جديد من النسخة المنظفة، دون حمل تاريخ المستودع القديم أو ملفاته الحساسة، مع إبقاء checkout الإنتاج `/opt/accounting-app` ومصدر نشره الحالي دون تغيير.

## ما تم

- أُنشئ مستودع Git فارغ محلياً بفرع `main` داخل cleanroom، وكان عدد الالتزامات عند الإنشاء صفراً.
- أضيفت `.gitattributes` لتوحيد الملفات النصية على LF وتعريف الأصول الثنائية الشائعة صراحة.
- رُحّلت الملفات المرشحة إلى الفهرس فقط؛ جميع الحالات كانت إضافات جديدة لأن التاريخ نظيف.
- مُنع إدراج `.env` وملفات البيئة، و`node_modules`، و`dist`، و`coverage`، و`supabase/.temp`، والمفاتيح والنسخ الاحتياطية والمخرجات التشغيلية وفق `.gitignore` وحاجز السلامة.
- أضيف `origin` داخل cleanroom فقط إلى المستودع الخاص الجديد `https://github.com/MohammedIsmail36/accounting-stores-app.git` بعد إثبات أنه متاح وفارغ تماماً، ثم دُفع فرع `main` لأول مرة مع ضبط تتبعه لـ`origin/main`.
- لم يُعدّل remote داخل checkout الإنتاج، ولم يتغير Nginx أو Docker أو أي قاعدة بيانات.

## تنظيف فرق Git

- كان العدد الأولي 498 ملفاً مرشحاً، وأصبحت الملفات المرحّلة 499 بعد إضافة `.gitattributes`.
- بعد توحيد LF كشف `git diff --cached --check` عدد 163 ملاحظة مسافات نهائية موزعة على 34 ملفاً قديماً.
- أزيلت المسافات النهائية ميكانيكياً فقط، ثم أزيل سطر فارغ إضافي من نهاية 9 ملفات.
- اجتاز فرق الفهرس بعدها `git diff --cached --check` بلا ملاحظات.

## القيود والخطوة التالية

- هذا التقرير لا يعلن اكتمال L6؛ أُنشئ الالتزام الأول المحلي بهوية Git المعتمدة وربط `origin` بعد التحقق من فراغ المستودع، ثم دُفع `main`. ما زالت حماية الفرع واختبار clone جديد وبواباته مهاماً معلقة.
- أُعيدت بوابة فرق Git وحاجز السلامة بعد إضافة التقرير وقبل إنشاء الالتزام الأول.
- لا يُغير `origin` في `/opt/accounting-app` أثناء L6، ولا يُنشر شيء إلى الإنتاج ضمن هذه المرحلة.
